# 1 验证目标

本文档用于手工验证 Content 服务“视频上传与发布”核心链路是否可用，覆盖以下业务闭环：

1. 用户注册/登录并获取 JWT。
2. 获取视频预签名上传地址。
3. 将本地视频上传到 MinIO。
4. 调用发布接口完成视频发布。
5. 由 Kafka 异步触发 worker，使用 FFmpeg 抽帧生成封面。
6. 在发布列表与 Feed 流中验证视频是否可见。
7. 验证封面图片与视频播放地址是否可以访问。

# 2 验证前提

## 2.1 测试资源

本次测试使用仓库内现成视频文件：

- `assets/demo_video.mp4`

## 2.2 配置要求

确保本地配置文件 [config.yaml](file:///D:/project/ticktok-service/config/config.yaml) 满足以下要求：

- MySQL 指向 `localhost:3306`
- Redis 指向 `localhost:6379`
- MinIO 指向 `localhost:19000`
- Kafka 指向 `localhost:9092`
- `media.ffmpeg_path: ffmpeg`

说明：

1. 如果使用 Docker 中的 `media-worker`，宿主机本地不需要安装 FFmpeg。
2. 如果改为本地运行 `task run-worker`，则宿主机需要能够直接执行 `ffmpeg` 命令。

## 2.3 依赖环境

先启动中间件环境：

```powershell
task docker-up
```

验证容器已启动：

- MySQL
- Redis
- MinIO
- Kafka
- media-worker

# 4 手工验证步骤

以下步骤以 PowerShell 为例。

## 4.1 注册测试用户

```powershell
$base = "http://localhost:8080"
$username = "content_e2e_" + (Get-Date -Format "yyyyMMddHHmmss")
$password = "Pass123456"

$registerBody = @{
  username = $username
  password = $password
} | ConvertTo-Json

$registerResp = Invoke-RestMethod `
  -Uri "$base/api/v1/auth/register" `
  -Method Post `
  -ContentType "application/json" `
  -Body $registerBody

$registerResp | ConvertTo-Json -Depth 5
```

预期结果：

- 返回 `access_token`
- 返回 `refresh_token`
- 返回 `user_id`

保存 Token 供后续步骤使用：

```powershell
$token = $registerResp.access_token
$userId = $registerResp.user_id
$headers = @{
  Authorization = "Bearer $token"
}
```

## 4.2 获取视频上传地址

```powershell
$title = "demo_video_e2e"

$uploadResp = Invoke-RestMethod `
  -Uri "$base/api/v1/publish/action/url?title=$title" `
  -Headers $headers `
  -Method Get

$uploadResp | ConvertTo-Json -Depth 5
```

预期结果：

- 返回 `upload_url`
- 返回 `video_id`

## 4.3 上传本地视频到 MinIO

```powershell
$asset = "D:\project\ticktok-service\assets\demo_video.mp4"

$putResp = Invoke-WebRequest `
  -Uri $uploadResp.upload_url `
  -Method Put `
  -InFile $asset `
  -ContentType "video/mp4" `
  -UseBasicParsing

$putResp.StatusCode
```

预期结果：

- HTTP 状态码为 `200`

## 4.4 确认发布视频

```powershell
$publishBody = @{
  video_id = [int64]$uploadResp.video_id
} | ConvertTo-Json

$publishResp = Invoke-RestMethod `
  -Uri "$base/api/v1/publish/action/confirm" `
  -Headers $headers `
  -Method Post `
  -ContentType "application/json" `
  -Body $publishBody

$publishResp | ConvertTo-Json -Depth 5
```

预期结果：

- 接口成功返回
- 数据库中视频状态由 Pending 变为 Published
- Content 服务向 Kafka 写入视频发布事件
- worker 开始异步抽帧

## 4.5 观察 worker 日志

```powershell
docker logs --tail 50 ticktok-media-worker
```

预期日志关键字：

- `Cover worker started`
- `Starting to extract cover`
- `Successfully processed cover`

这说明 worker 已完成以下动作：

1. 从 MinIO 下载源视频到本地临时目录。
2. 调用 FFmpeg 从本地视频文件抽取封面。
3. 将封面图片上传回 MinIO。
4. 更新数据库中的封面可访问地址。

## 4.6 查询发布列表

```powershell
$publishListResp = Invoke-RestMethod `
  -Uri "$base/api/v1/publish/list?user_id=$userId" `
  -Headers $headers `
  -Method Get

$publishListResp | ConvertTo-Json -Depth 6
```

预期结果：

- `video_list` 中存在本次发布的 `video_id`
- `play_url` 指向 MinIO 中的视频文件
- `cover_url` 指向 MinIO 中的封面图片

## 4.7 查询 Feed 流

```powershell
$feedResp = Invoke-RestMethod `
  -Uri "$base/api/v1/feed?last_score=0&last_id=0" `
  -Method Get

$feedResp | ConvertTo-Json -Depth 6
```

预期结果：

- `video_list` 中可以查到本次发布的视频
- 说明 `PublishVideo` 已成功把视频写入 Feed 缓存/查询链路

## 4.8 验证视频与封面可访问

访问发布列表中返回的两个地址：

- `play_url`
- `cover_url`

也可以直接用 PowerShell 验证：

```powershell
$video = $publishListResp.video_list | Where-Object { $_.id -eq $uploadResp.video_id } | Select-Object -First 1

$tmpCover = Join-Path $env:TEMP ("cover_" + $uploadResp.video_id + ".jpg")

Invoke-WebRequest `
  -Uri $video.cover_url `
  -OutFile $tmpCover `
  -UseBasicParsing

(Get-Item $tmpCover).Length
```

预期结果：

- 封面下载成功
- 文件大小大于 `0`

## 4.9 测试点赞

对刚发布的视频执行点赞：

```powershell
$favoriteResp = Invoke-RestMethod `
  -Uri "$base/api/v1/favorite/action" `
  -Headers $headers `
  -Method Post `
  -ContentType "application/json" `
  -Body (@{
    video_id = [int64]$uploadResp.video_id
    action_type = 1
  } | ConvertTo-Json)

$favoriteResp | ConvertTo-Json -Depth 5
```

预期结果：

- 接口成功返回
- 点赞关系写入 Redis 热路径
- Kafka 收到点赞关系事件
- Feed 或发布列表中的 `favorite_count` 很快变为 `1`

## 4.10 验证点赞状态与点赞数

因为 Feed 是开放接口，验证 `is_favorite` 时需要带上 token：

```powershell

  -Uri "$base/api/v1/feed?last_score=0&last_id=0&token=$token" `
  -Method Get

$likedVideo = $feedAfterLikeResp.video_list | Where-Object { $_.id -eq $uploadResp.video_id } | Select-Object -First 1

$likedVideo | ConvertTo-Json -Depth 6
```

预期结果：

- 能查到本次视频
- `is_favorite = true`
- `favorite_count >= 1`

# 5 一次性验证脚本

如果希望将上述步骤快速串起来，可以使用如下 PowerShell 脚本：

```powershell
$ErrorActionPreference = "Stop"
$base = "http://localhost:8080"
$asset = "D:\project\ticktok-service\assets\demo_video.mp4"
$username = "content_e2e_" + (Get-Date -Format "yyyyMMddHHmmss")
$password = "Pass123456"

$register = Invoke-RestMethod -Uri "$base/api/v1/auth/register" -Method Post -ContentType "application/json" -Body (@{
  username = $username
  password = $password
} | ConvertTo-Json)

$token = $register.access_token
$userId = $register.user_id
$headers = @{ Authorization = "Bearer $token" }

$upload = Invoke-RestMethod -Uri "$base/api/v1/publish/action/url?title=demo_video_e2e" -Headers $headers -Method Get

$uploadResp = Invoke-WebRequest -Uri $upload.upload_url -Method Put -InFile $asset -ContentType "video/mp4" -UseBasicParsing

$publish = Invoke-RestMethod -Uri "$base/api/v1/publish/action/confirm" -Headers $headers -Method Post -ContentType "application/json" -Body (@{
  video_id = [int64]$upload.video_id
} | ConvertTo-Json)

$favorite = Invoke-RestMethod -Uri "$base/api/v1/favorite/action" -Headers $headers -Method Post -ContentType "application/json" -Body (@{
  video_id = [int64]$upload.video_id
  action_type = 1
} | ConvertTo-Json)

$comment = Invoke-RestMethod -Uri "$base/api/v1/comment/action" -Headers $headers -Method Post -ContentType "application/json" -Body (@{
  video_id = [int64]$upload.video_id
  action_type = 1
  comment_text = "first comment"
} | ConvertTo-Json)

$publishedVideo = $null
$coverReady = $false

for ($i = 0; $i -lt 12; $i++) {
  Start-Sleep -Seconds 2
  $publishList = Invoke-RestMethod -Uri "$base/api/v1/publish/list?user_id=$userId" -Headers $headers -Method Get
  $publishedVideo = $publishList.video_list | Where-Object { $_.id -eq $upload.video_id } | Select-Object -First 1
  if (-not $publishedVideo) { continue }

  try {
    $tmpCover = Join-Path $env:TEMP ("cover_test_" + $upload.video_id + ".jpg")
    Invoke-WebRequest -Uri $publishedVideo.cover_url -OutFile $tmpCover -UseBasicParsing | Out-Null
    if ((Test-Path $tmpCover) -and ((Get-Item $tmpCover).Length -gt 0)) {
      $coverReady = $true
      Remove-Item $tmpCover -Force
      break
    }
  } catch {}
}

$feedAfterLike = Invoke-RestMethod -Uri "$base/api/v1/feed?last_score=0&last_id=0&token=$token" -Method Get
$feedVideoAfterLike = $feedAfterLike.video_list | Where-Object { $_.id -eq $upload.video_id } | Select-Object -First 1

$commentList = Invoke-RestMethod -Uri "$base/api/v1/comment/list?video_id=$($upload.video_id)" -Headers $headers -Method Get
$commentItem = $commentList.comment_list | Where-Object { $_.id -eq $comment.comment.id } | Select-Object -First 1

$unfavorite = Invoke-RestMethod -Uri "$base/api/v1/favorite/action" -Headers $headers -Method Post -ContentType "application/json" -Body (@{
  video_id = [int64]$upload.video_id
  action_type = 2
} | ConvertTo-Json)

$deleteComment = Invoke-RestMethod -Uri "$base/api/v1/comment/action" -Headers $headers -Method Post -ContentType "application/json" -Body (@{
  video_id = [int64]$upload.video_id
  action_type = 2
  comment_id = [int64]$comment.comment.id
} | ConvertTo-Json)

Start-Sleep -Seconds 6

$feedAfterUnlike = Invoke-RestMethod -Uri "$base/api/v1/feed?last_score=0&last_id=0&token=$token" -Method Get
$feedVideoAfterUnlike = $feedAfterUnlike.video_list | Where-Object { $_.id -eq $upload.video_id } | Select-Object -First 1

$commentListAfterDelete = Invoke-RestMethod -Uri "$base/api/v1/comment/list?video_id=$($upload.video_id)" -Headers $headers -Method Get
$deletedStillExists = $commentListAfterDelete.comment_list | Where-Object { $_.id -eq $comment.comment.id } | Select-Object -First 1

[pscustomobject]@{
  username = $username
  user_id = $userId
  video_id = $upload.video_id
  upload_status = $uploadResp.StatusCode
  publish_list_contains_video = [bool]$publishedVideo
  cover_url = $publishedVideo.cover_url
  cover_ready = $coverReady
  play_url = $publishedVideo.play_url
  liked_is_favorite = [bool]$feedVideoAfterLike.is_favorite
  liked_favorite_count = [int64]$feedVideoAfterLike.favorite_count
  liked_comment_count = [int64]$feedVideoAfterLike.comment_count
  comment_created = [bool]$commentItem
  final_favorite_count = [int64]$feedVideoAfterUnlike.favorite_count
  final_comment_count = [int64]$feedVideoAfterUnlike.comment_count
  comment_deleted = -not [bool]$deletedStillExists
} | ConvertTo-Json -Depth 5
```

# 6 验收标准

当以下条件同时满足时，可判定本次“上传与发布”链路验证通过：

1. 用户注册成功，获取到有效 Token。
2. 获取上传地址成功，并返回 `video_id`。
3. 视频文件成功上传到 MinIO。
4. `PublishVideo` 成功返回。
5. worker 日志出现抽帧成功记录。
6. 发布列表中能查到新视频。
7. Feed 流中能查到新视频。
8. `play_url` 和 `cover_url` 都能正常访问。
9. 点赞后 `favorite_count` 递增，且 `is_favorite = true`。
10. 取消点赞后 `favorite_count` 最终恢复。
11. 发表评论后评论列表可见新评论。
12. 删除评论后评论列表不再返回该评论，`comment_count` 最终恢复。

# 7 常见问题排查

## 7.1 端口被占用

如果 `10001`、`10002`、`8080` 端口被占用，服务会启动失败。

排查命令：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 8080,10001,10002
```

## 7.2 worker 无法消费 Kafka

重点检查：

1. Kafka 是否正常启动。
2. Docker 内 worker 使用的 broker 是否为容器内地址。
3. 本地服务使用的 broker 是否为宿主机地址。

## 7.3 封面生成失败

重点检查：

1. `ticktok-media-worker` 日志中是否出现 FFmpeg 执行报错。
2. MinIO 中是否存在对应的 `video_id.mp4`。
3. worker 是否已先将视频下载到本地临时文件再抽帧。

## 7.4 封面地址不可访问

重点检查：

1. `cover_url` 是否被写成容器内部地址，例如 `minio:9000`
2. 对外可访问地址应为 `localhost:19000`

## 7.5 点赞状态异常

重点检查：

1. 请求头中是否携带 `Authorization: Bearer <token>`
2. 查询 Feed 时是否把 token 作为 query 参数带上
3. `ticktok-media-worker` 是否正常消费点赞事件
4. Redis 中 `like:status:{videoId}:{userId}` 是否已更新

## 7.6 评论列表异常

重点检查：

1. 评论是否已成功落入 MySQL `video_comments`
2. Redis 中 `comment:list:{videoId}` 与 `comment:detail:{commentId}` 是否存在
3. 删除评论时是否使用了正确的 `comment_id`
4. 当前删除请求用户是否就是评论作者
